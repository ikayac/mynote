## 1. なぜ様々な確率分布を選ぶのか？（DGPの思想）

「最小二乗法」は、ただ直線を引いてズレを測るだけでした。しかし最尤推定（MLE）では、**「このデータはどういうルール（DGP: Data Generating Process）に従って生まれてきたのだろう？」** というモデルの仮定が絶対的に必要になります。間違った分布を選べば、あり得ない予測（例：「今日の事故件数はマイナス2件」）を生み出してしまいます。

以下では、代表的な4つの確率分布について、AIがどのようにデータ（DGP）をシミュレーションし、尤度関数を定義したかを解説します。

## 2. Numba (`@jit`) による反復計算の高速化

これら4つの尤度のスクラッチコードは、すべてピュアなPythonの `for` ループで書かれています。本来Pythonの `for` ループは非常に遅く、スライダーを動かすたびに再計算が走るUIでは致命的なもたつき（ラグ）が発生します。

これを解決するため、アプリの関数にはすべて **Numba** の `@jit` デコレータを付与しました。

```python
from numba import jit
import numpy as np

@jit(nopython=True)
def ll_poisson(data, lam):
    ll = 0.0
    for i in range(len(data)):
        if lam <= 0: return -np.inf
        ll += data[i] * np.log(lam) - lam
    return ll
```

> [!tip] 高速化の魔法
> `@jit(nopython=True)` をつけるだけで、裏側でPythonコードがC言語・機械語レベルにJITコンパイルされ、速度が数百倍に跳ね上がります。今後のMCMC実装などには必須のテクニックです。

## 3. 全4分布の DGP と 記号マッピング

### ① 正規分布 (Gaussian Distribution)
*   **データの素性 (DGP)**: 連続した実数値（身長など）。アプリでは「真の平均50、標準偏差10」から `np.random.normal(50.0, 10.0, 100)` で100名の生徒の点数などをシミュレート。

| 原典・一般の数式記号 | 意味・役割 | 今回のコード変数名 | 備考 |
| :--- | :--- | :--- | :--- |
| $\mu$ | 平均（山の中心位置） | `user_p1` (Slider), `mu` | 最尤推定量は「標本平均」 |
| $\sigma$ | 標準偏差（山の広がり幅） | `user_p2` (Slider), `sigma` | |
| $\log L(\mu, \sigma)$ | 対数尤度 | `ll_normal()` の返り値 | |

### ② ポアソン分布 (Poisson Distribution)
*   **データの素性 (DGP)**: 0以上の整数値（カウントデータ）。アプリでは「平均発生回数 3.5件」から `np.random.poisson(3.5, 100)` で100日間の事故件数などをシミュレート。

| 原典・一般の数式記号 | 意味・役割 | 今回のコード変数名 | 備考 |
| :--- | :--- | :--- | :--- |
| $\lambda$ (ラムダ) | 平均発生回数（強度） | `user_p1` (Slider), `lam` | 最尤推定量は「標本平均」 |
| $x_i !$ (階乗) | 数式上の分母 | （省略・計算せず） | パラメータ $\lambda$ に関与しない定数なので最適化計算から除外 |
| $\log L(\lambda)$ | 対数尤度 | `ll_poisson()` の返り値 | |

### ③ 二項分布 (Binomial / Bernoulli Distribution)
*   **データの素性 (DGP)**: 「成功(1)か失敗(0)か」の2値データ。アプリでは「成功確率 70% (0.7)」のコインを100回投げた結果を `np.random.binomial(1, 0.7, 100)` でシミュレート。

| 原典・一般の数式記号 | 意味・役割 | 今回のコード変数名 | 備考 |
| :--- | :--- | :--- | :--- |
| $p$ または $\theta$ | 1回の試行の成功確率 | `user_p1` (Slider), `p` | 原著によっては $\theta$ や $\pi$ で表現される |
| $N$ または $n$ | 試行回数 | `data`の要素数 | アプリでは1回のベルヌーイ試行($n=1$)を100要素用意した |
| $\log L(p)$ | 対数尤度 | `ll_binomial()` の返り値| |

### ④ 指数分布 (Exponential Distribution)
*   **データの素性 (DGP)**: 「次の現象が起きるまでの待ち時間」（非負の連続値）。アプリでは「発生率 0.2」に従う待ち時間を `np.random.exponential(1.0/0.2, 100)` でシミュレート。

| 原典・一般の数式記号 | 意味・役割 | 今回のコード変数名 | 備考 |
| :--- | :--- | :--- | :--- |
| $\lambda$ (ラムダ) | 単位時間あたりの発生率 | `user_p1` (Slider), `lam` | 平均待ち時間は $1/\lambda$ となる点に注意 |
| $\log L(\lambda)$ | 対数尤度 | `ll_exponential()`の返り値| 最尤推定量は $\lambda = 1 / (\text{標本平均})$ |
